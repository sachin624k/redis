# 02 — Setup Local Redis with Node.js

## 1. Docker Compose Setup

Create `docker-compose.yml` in the root `Redis` folder to run Redis and MongoDB locally.

```yaml
services:
  redis:
    image: redis:7-alpine
    container_name: chai_aur_redis
    ports:
      - "6379:6379"
    command: ["redis-server", "--appendonly", "yes"]
    volumes:
      - redis_data:/data

  mongo:
    image: mongo:7
    container_name: chai_aur_mongo
    ports:
      - "27017:27017"
    environment:
      MONGO_INITDB_DATABASE: chai_aur_db
    volumes:
      - mongo_data:/data/db

volumes:
  redis_data:
  mongo_data:
```

### Important Docker Commands

```bash
docker compose up
```

- Starts the containers in the foreground.
- Displays container logs in the current terminal.
- Pressing `Ctrl + C` stops the foreground Compose services.

```bash
docker compose up -d
```

- Starts containers in detached mode (background).
- Frees the terminal for running the backend.
- Use `docker compose logs -f` to view live logs.

```bash
docker compose ps
docker compose down
```

- `ps` → checks container status.
- `down` → stops and removes containers and the Compose network.
- Named volumes are preserved by default, so database data remains.

**Remember:** Docker Desktop must be running before using Docker Compose.

## 3. Redis Client Connection

```js
import Redis from "ioredis";

const redis = new Redis(process.env.REDIS_URL || "redis://localhost:6379");
```

### What does this mean?

**Redis client:** An object that lets our Node.js application communicate with the Redis server.

- `new Redis(...)` → creates a Redis client and starts connecting to Redis.
- `process.env.REDIS_URL` → reads the Redis connection URL from an environment variable.
- `|| "redis://localhost:6379"` → uses the local Redis URL if `REDIS_URL` is not set.
- `localhost` → refers to the same machine where the Node.js process is running.
- `6379` → Redis's default port.

**Why do we create a Redis client?**

Our application needs a client to send Redis commands such as `PING`, `GET`, `SET`, and `DEL`.

Create a client that can be shared across the parts of the application that need it, rather than creating a new connection for every request.

**Important:** If Node.js runs directly on your Mac and Redis runs in Docker with port `6379:6379`, `localhost:6379` works. If Node.js runs inside another container, use the Redis Compose service name (`redis`) and its container port instead.

## 4. Redis Health Check API

```js
app.get("/redis", async (req, res) => {
  const reply = await redis.ping();
  res.json({ redis: reply });
});
```

### Understanding the new Redis parts

**`await redis.ping()`**

- Sends the Redis `PING` command through the Redis client.
- Redis responds with `PONG` if it is reachable and responding.
- `await` waits for the command to finish before continuing.

**`res.json({ redis: reply })`**

- Sends the reply as JSON.
- Since `reply` is `"PONG"`, the response is:

```json
{
  "redis": "PONG"
}
```

### What is PING?

`PING` is a simple Redis command used to check whether the Redis server is responding.

```text
Node.js Backend → Redis: PING
Node.js Backend ← Redis: PONG
```

**Remember:** `PONG` confirms that the Redis server responded to the command. It is a basic connectivity check, not a complete test of every Redis operation.

## 5. Test with Postman

Start Docker:

Start the Node.js backend from `02-setup-local-redis`:


```json

  "redis": "PONG"
}
```

### Test MongoDB

- Method: `GET`
- URL: `http://localhost:3000/mongo`

Expected response:

```json
{
  "mongo": "connected",
  "database": "chai_aur_db"
}
```

The MongoDB route connects using Mongoose and returns the connected database name. The connection is reused on subsequent requests while it remains open.

## 6. Key Concepts to Remember

- **Redis server** → stores and processes data in memory.
- **Redis client** → allows our backend to communicate with Redis.
- **ioredis** → Node.js library used to communicate with Redis.
- **PING / PONG** → basic Redis connectivity check.
- **Express route** → an endpoint that handles an HTTP request.
- **Port 3000** → our backend server.
- **Port 6379** → Redis server.
- **Port 27017** → MongoDB server.
- **Mongoose** → ODM library for MongoDB.
- **Docker Compose** → runs multiple services together.
- **Named volumes** → preserve container data across normal container removal and recreation.

**Core idea:** The Express backend uses clients such as `ioredis` and Mongoose to communicate with Redis and MongoDB. Postman sends HTTP requests to the backend; it does not directly communicate with either database in this example.
